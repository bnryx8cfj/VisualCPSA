CPSA 4 Canonical UML Metamodel

1. Purpose

This metamodel defines the canonical structural UML model for the CPSA 4 DSL reference. It represents CPSA declarations, protocol structure, message algebra constructs, strand-space analysis concepts, channels, facts, assumptions, goals, rule formulas, and related logical structures.

The metamodel is intended to support:

  1. A complete CPSA 4 DSL language reference.
  2. A canonical UML metamodel reused across all declaration chapters.
  3. PlantUML and SVG diagrams derived from the same model.
  4. Chapter-specific highlighting without changing the underlying model.

2. Package Overview

2.1 Document Package

The Document Package models a CPSA input or output document and its top-level declaration structure.

Citation Note: Document Package

The CPSADocument and TopLevelDeclaration classes are metamodel abstractions for CPSA's S-expression input-output style and top-level declaration structure. CPSA documentation describes the analyzer as reading input problems and writing S-expression output, and the user guide states that input syntax is essentially the same as output syntax. 【5-a3b0b0】【4-5b9322】

4. Protocol Package

Citation Note: Protocol Package

The Protocol, Role, and Rule classes reflect CPSA 4's protocol structure. The CPSA foundation paper states that protocols in CPSA 4 include both roles and rules, which justifies modeling Role and Rule as contents of Protocol. 【6-0924c4】

The Trace, Event, SendEvent, and ReceiveEvent classes are grounded in strand-space theory, where strands are sequences of transmission and reception events. 【8-3e1455】【9-e4a22f】

The Channel and ChannelEvent classes are included because CPSA 4 extends ordinary communication events with optional channel annotations, and the CPSA foundation paper distinguishes authenticated, confidential, secure, and plain channel behavior. 【6-0924c4】

5. Message Algebra Package

Citation Note: Message Algebra Package

The Term, Variable, Sort, FunctionApplication, Operator, and concrete operator classes model CPSA's order-sorted message algebra. The CPSA foundation paper describes messages as the carrier set of a term algebra and states that variables have unique sorts in an order-sorted algebra. 【6-0924c4】【7-7756e1】

The basic and Diffie-Hellman operator classes follow the CPSA 4 manual's algebra feature discussion, including generic messages, long-term keys, hashing, constants, and Diffie-Hellman modeling. 【1-817011】

6. Analysis Package

Citation Note: Analysis Package

The Skeleton, Strand, Node, Bundle, Shape, and RealizedExecution classes reflect CPSA's strand-space analysis vocabulary. CPSA documentation describes shapes as essentially different executions compatible with initial behavior, and strand-space literature defines strands as sequences of events and bundles as causally structured executions. 【2-cf98f8】【8-3e1455】【9-e4a22f】

The Fact, PrecedenceRelation, NonOrigAssumption, UniqOrigAssumption, and UniqGenAssumption classes represent structural analysis constraints and assumptions used in CPSA-style skeleton analysis. Facts and channels are explicitly identified as CPSA 4 additions to bundles and skeletons in the foundation paper. 【6-0924c4】

7. Goal Package

Citation Note: Goal Package

The Goal, Formula, AtomicFormula, quantified formula, Boolean formula, Predicate, and PredicateApplication classes model the structural form of CPSA security goals and rule formulas. Ramsdell describes CPSA goals in terms of formulas over shape-analysis results and shows how logical deduction can be used to determine whether a goal is satisfied. 【10-074f2f】【11-ffa6be】

The formula hierarchy in this metamodel is an abstraction suitable for UML modeling. It is inspired by Ramsdell's formal treatment of security goals as quantified logical formulas and CPSA's strand-oriented goal language. 【10-074f2f】【2-cf98f8】

Source Basis

The metamodel is based on the CPSA 4 public documentation and repository materials, including the CPSA 4 manual, the MITRE CPSA GitHub repository, the CPSA user guide, the CPSA foundation paper on strand spaces with channels and rules, the original strand-space literature, and Ramsdell's work on deriving security goals from shape analysis sentences. The CPSA 4 manual identifies Moses D. Liskov, John D. Ramsdell, Joshua D. Guttman, and Paul D. Rowe as authors and describes CPSA 4 as the Cryptographic Protocol Shapes Analyzer manual for CPSA Version 4.4.8, dated February 27, 2026. 【1-817011】 The MITRE CPSA GitHub repository identifies CPSA as an experimental Cryptographic Protocol Shapes Analyzer and provides source, documentation, examples, and tooling materials. 【2-cf98f8】【3-c98920】

Key source-derived modeling commitments:

  • CPSA analyzes protocol executions by attempting to enumerate the essentially different executions possible for a cryptographic protocol, which CPSA calls the protocol's shapes. 【2-cf98f8】【4-5b9322】
  • CPSA input and output are S-expression based, and the CPSA user guide states that the input syntax is essentially the same as the output syntax. 【5-a3b0b0】
  • A CPSA document-level metamodel class is included to represent a CPSA S-expression document as a container for top-level declarations. This is a metamodel abstraction derived from CPSA's S-expression document model and tool input-output convention. 【5-a3b0b0】【2-cf98f8】
  • Protocols include roles and rules in CPSA 4; the foundation paper states that protocols have been redefined so that they include both roles and rules. 【6-0924c4】
  • CPSA 4 adds channels and facts to the strand-space formalism used by CPSA; the foundation paper says that channels and facts have been added to bundles and skeletons. 【6-0924c4】
  • CPSA 4 communication events may optionally occur on a channel, and channels are interpreted in terms of authenticated, confidential, and secure communication. 【6-0924c4】
  • CPSA uses a message-algebra formalism in which messages form the carrier set of a term algebra, variables have sorts, and predicate symbols are parameters to the strand-space formalism. 【6-0924c4】【7-7756e1】
  • The strand-space basis for this metamodel is grounded in the original strand-space literature, which describes a strand as a sequence of events and a strand space as a collection of strands with graph structure generated by causal interaction. 【8-3e1455】【9-e4a22f】
  • The goal-language portion of the metamodel is informed by Ramsdell's treatment of security goals as formulas over CPSA shape-analysis results and by the CPSA repository statement that CPSA 4 implemented a strand-oriented security goal language. 【10-074f2f】【2-cf98f8】
  • Examples in this metamodel that refer to shapes, skeletons, bundles, events, nodes, channels, facts, rules, and goal formulas are structural abstractions inspired by CPSA documentation and strand-space research, not direct quotations of CPSA grammar. 【1-817011】【6-0924c4】【10-074f2f】

Citation Policy for This Metamodel

Inline citations are attached to source-derived claims, paraphrases, and examples. UML class names, association names, and diagram labels are metamodel design artifacts derived from source terminology. Where a class is an abstraction rather than an explicitly named CPSA syntax form, the surrounding explanatory prose identifies the source basis.

References that do not expose an ISBN or DOI in the consulted public source are marked as having no DOI or ISBN found in the consulted source.

Example Attribution and Use

Examples that illustrate protocol shapes, skeletons, bundles, strands, events, and nodes are inspired by CPSA's description of shape analysis and the strand-space literature. CPSA describes its analysis as discovering shapes compatible with an initial behavior, while strand-space work describes strands as event sequences and bundles as causally organized collections of nodes. 【2-cf98f8】【8-3e1455】【9-e4a22f】

Examples that use channels, channel events, facts, and rules are inspired by the CPSA 4 foundation paper, which states that channels and facts were added to bundles and skeletons and that protocols were redefined to include roles and rules. 【6-0924c4】

Examples that express authentication or secrecy goals using formulas, predicates, quantifiers, conjunctions, implications, or disjunctions are inspired by Ramsdell's work on deducing security goals from shape-analysis sentences. Ramsdell presents security goals as logical formulas evaluated against CPSA shape-analysis results. 【10-074f2f】【11-ffa6be】

Needham-Schroeder or Needham-Schroeder-Lowe examples, if used in later chapters, must be explicitly attributed to the Needham-Schroeder protocol lineage and to strand-space analyses that discuss the Needham-Schroeder-Lowe protocol and the original Needham-Schroeder failure. 【8-3e1455】【9-e4a22f】
