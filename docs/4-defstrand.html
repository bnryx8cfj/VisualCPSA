Chapter 4: defstrand

4.1 Overview

The defstrand construct is used within a CPSA skeleton to instantiate a role defined in a protocol. A strand represents a partially or fully realized execution of a protocol role and provides bindings between role variables and specific terms appearing in the analysis scenario.

From the strand-space perspective, a strand is an ordered sequence of protocol events corresponding to one execution instance of a role. A defstrand declaration introduces such an execution instance into a skeleton.

4.2 Purpose

The defstrand declaration serves four primary purposes:

  1. Instantiates a protocol role within a skeleton.
  2. Defines the strand height to be considered during analysis.
  3. Binds role variables to concrete terms.
  4. Establishes the initial assumptions from which CPSA derives shapes and realized executions.

A skeleton without strands contains no protocol participants. Consequently, defstrand declarations provide the protocol behavior that CPSA analyzes.

4.3 Semantics

A defstrand declaration denotes:

  • One instance of a protocol role.
  • A prefix of that role's trace.
  • A collection of variable substitutions.
  • A participant whose execution contributes nodes to the containing skeleton.

Conceptually:

defstrand(Role, Height, Bindings)

represents:

A strand whose trace is derived from the referenced role and whose visible execution consists of the first Height events of that role under the specified substitution.

A strand is not merely a syntactic construct. It represents a semantic execution object participating in:

  • Authentication reasoning
  • Secrecy reasoning
  • Shape generation
  • Realized execution construction
  • Bundle derivation

4.4 Concrete Syntax

General Form

(defstrand role-name height
  (var1 value1)
  (var2 value2)
  ...
)

Informal Syntax Description

A defstrand declaration consists of:

  1. The keyword defstrand
  2. A role identifier
  3. A strand height
  4. Zero or more variable bindings

Components

Component Meaning
defstrand Strand declaration keyword
role-name Referenced role
height Number of events included
Binding pair Variable substitution

4.5 Parameters and Attributes

Role Reference

Identifies the role from which the strand is instantiated.

Example:

(defstrand initiator 3 ...)

Height

Specifies the number of events from the role trace that are included in the skeleton.

Example:

(defstrand responder 2 ...)

Variable Bindings

Bind role variables to specific terms.

Example:

(a alice)
(b bob)
(n1 nonce1)

4.8 Cardinality Constraints

Role Constraint

A strand SHALL reference exactly one role.

Skeleton Constraint

A skeleton MAY contain zero or more strands.

Node Constraint

A strand MAY contain zero or more nodes.

Height Constraint

height >= 0

Trace Constraint

height <= length(role.trace)

4.12 CPSA Processing Semantics

During CPSA analysis:

  1. Validate role reference.
  2. Validate strand height.
  3. Validate variable bindings.
  4. Apply substitutions to role variables.
  5. Construct strand nodes from the role trace.
  6. Create node ordering constraints.
  7. Derive origination assumptions.
  8. Generate successor skeletons.
  9. Compute possible shapes.
  10. Construct realized executions.

4.13 Relationship to Strand-Space Theory

Strand

A defstrand corresponds directly to a strand-space strand.

Nodes

Each event occurrence becomes a node.

Trace

A role trace determines node ordering.

Skeleton

A collection of strands forms a skeleton.

Shape

Shape analysis derives minimal realized executions extending the skeleton.

Bundle

Bundles represent complete protocol executions containing the strand.

4.14 Common Modeling Mistakes

Invalid Height

Incorrect:

(defstrand initiator 20)

when the role trace contains fewer than twenty events.

Missing Variable Bindings

Incorrect:

(defstrand initiator 3)

when required role variables have not been assigned values.

Incorrect Role Reference

Referencing a role not defined within the protocol.

Inconsistent Bindings

Incorrect:

(a alice)
(a bob)

for the same variable context.

Redundant Strands

Introducing duplicate strands that contribute no new analytical information.

4.18 Complete Examples

Example 1: Needham-Schroeder Initiator Strand

(defskeleton ns
  (vars
    (a b name)
    (n1 text))

  (defstrand init 3
    (a a)
    (b b)
    (n1 n1)))

Interpretation

The skeleton contains:

  • One instantiated initiator role
  • Height 3
  • Explicit bindings for a, b, and n1

CPSA analyzes all executions consistent with this partial execution.

Example 2: Responder Strand

(defstrand resp 2
  (a alice)
  (b bob)
  (n1 nonce1))

Interpretation

Represents a responder role observed through the first two events of its trace.

4.19 Validation Checklist

A valid defstrand declaration satisfies all of the following:

  • Role exists.
  • Protocol exists.
  • Height is non-negative.
  • Height does not exceed trace length.
  • Variable substitutions are type-correct.
  • Sort constraints are satisfied.
  • Strand belongs to a skeleton.
  • Generated nodes are consistent with the role trace.
